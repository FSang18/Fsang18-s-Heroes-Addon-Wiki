    Render Layers

    Render layers draw extra models or effects on top of an entity. These are the render layers Argon adds.

    3 listed · Argon 1.0.0

    Anchored Lightning Sparks

    IDargon:anchored_lightning_sparks
    Like Palladium's Lightning Sparks, but the sparks can be tied to named body part bones using the same "anchors" as the Thrusters layer.

    KeyTypeDescriptionRequiredFallback
    frequencyFloatThe frequency of the sparks.✗0.5
    amountIntegerHow many sparks spawn each time, per anchor (or for the whole entity if "anchors" is empty).✗5
    render_settingsLaser Renderer SettingsThe render settings for the sparks.✓/
    anchorsstring[]Bones to spawn sparks at, e.g. "head" or "right_arm". Each gets its own spark cycle. Empty spawns them anywhere on the entity, like palladium:lightning_sparks.✗[]
    anchor_sizeFloatOnly relevant when "anchors" isn't empty: how far, in blocks, sparks jitter from the anchor point.✗0.3
    offsetVector 3D[x, y, z] offset from the anchor (or the entity if "anchors" is empty), so sparks can sit off the bone's pivot.✗[ 0, 0, 0 ]
    transformationIdentifier,
    Identifier[]    		Transformation ID(s). The layer only shows while one of these transformations is shown, on the transformed model. Without this field the layer is hidden while a transformation model is shown. Layers inside a compound layer without their own value use the one of the compound.✗/
    shrink_player_partscape
    jacket
    left_sleeve
    right_sleeve
    left_pants_leg
    right_pants_leg
    hat    		Skin overlay part(s) that are scaled down slightly while this layer is visible, so they don't stick out of the layer's model. "cape" has no effect.✗/

    Cloth Render Layer

    IDargon:cloth
    Renders a simulated cloth grid (a cape by default) that flows, bends and trails behind the wearer instead of turning as one flat plane.

    KeyTypeDescriptionRequiredFallback
    attachmentback
    left_arm
    right_arm
    waist    		Which part of the cloth grid is pinned to the wearer: "back" (cape), "left_arm" or "right_arm" (draped along an arm), or "waist" (skirt or kilt, a box-shaped loop around the hips).✗back
    materialIdentifier,
    Inline Material Object    		A registered material id (e.g. "argon:heavy") or an inline object overriding individual physics properties.✗argon:standard
    sizeVector 2D[length, width] of the cloth at rest, in blocks. For a "waist" attachment, "width" is the half-width of the left and right sides of the box. "depth" sets the front and back.✗[ 1.8, 1 ]
    segmentsVector 2D[segments_x, segments_y]: simulation columns/rows. More = smoother bending at a performance cost.✗[ 4, 8 ]
    wrapFloat"back" attachment only. Curves the pinned edge forward so it hugs the wearer's sides, turning a flat cape into a wrap-around cloak. 0 is flat.✗0.0
    depthFloat"waist" attachment only. Half-depth of the front and back sides, in blocks. Usually smaller than "width", since players are thinner front to back. Defaults to "width".✗/
    pitch_influenceFloat"waist" attachment only. While crouching, the garment follows the body's pitch as one piece. This scales how much, 0 ignores it and 1 follows fully.✗0.6
    hem_pitch_fractionFloatCurrently unused. Kept so existing configs that set it still load.✗0.25
    attachVector 3D[x, y, z] offset of the attach point from the neck, in wearer space. Y=0 is neck height and higher Y goes down. A cape needs a positive Z to sit behind. For "waist" use X=0, Z=0 and Y about 0.75-0.9.✗[ 0, 0.1, 0.4 ]
    taperFloat"back" attachment only. Width at the shoulders as a fraction of the width at the hem, 0.05 to 1. Below 1 the cloth is a trapezoid that flares out to "width" at the hem. 1 is a plain rectangle.✗1.0
    aerodynamicsCloth AerodynamicsHow the cloth reacts to the wearer's real speed, not the selected flight level. Each part is documented in the tables below.✗{}
    textureTexture Reference,
    Dynamic Texture    		The texture for the cloth. UVs stay stable across the grid however the cloth deforms.✓/

    Fade Render Layer

    IDargon:fade
    Wraps another render layer and draws it at a changing opacity so it can fade in and out. Put the wrapped layer's conditions inside "layer". Nothing is drawn at opacity 0.

    KeyTypeDescriptionRequiredFallback
    opacityFloat / Value(Dynamic) 0 to 1, how opaque the wrapped layer is. Usually an ability's eased animation timer, e.g. palladium.get_animation_timer_eased('namespace:power#ability'), which already runs 0 to 1.✗1.0
    layerRender LayersThe render layer to draw, written exactly as it would be on its own, including its "conditions".✓/

    {
  "type": "argon:fade",
  "opacity": {
    "type": "palladium:molang_float",
    "molang": "palladium.get_animation_timer_eased('example:power#some_ability')"
  },
  "layer": {
    "texture": {
      "type": "palladium:eye_selection",
      "color": "#6b6b6b"
    }
  }
}
